## Decisions so far

- [核实旧系统完整业务与权限基线](issues/01-legacy-business-baseline.md)：已形成主要业务、权限和后台能力的代码证据清单；生产使用情况和完整流程仍需业务及环境验证。
- [核实必须保留的登录、审批和历史资产契约](issues/02-preserved-integration-contracts.md)：已核实身份、SDK3审批与历史标识/附件契约，并列出Windows验证清单；运行兼容性、整体幂等性和真实资产规模未证实。
- [研究重建技术候选与业务接口复用条件](issues/03-rebuild-technology-options.md)：已按官方来源比较现代 .NET 产品路线及旧集成过渡条件，形成候选与核验前提；后续技术选择记录在产品技术路线事项。
- [界定完整业务覆盖与保留调整清单](issues/04-full-business-scope.md)：十组业务全部纳入首期，保留外部平台并重做法务端与集成，由集团法务统一确认范围；暂无其他明确必做项，具体流程后续设计。
- [明确新产品角色、流程和关键业务模型](issues/05-product-roles-workflows.md)：已确认角色授权与案件正常主流程基线，程序阶段按事实更新，正常履行办结后由授权人员核对关闭；详细规则及后续细化边界保留在事项中。
- [确认上线、部署和维护硬约束](issues/06-delivery-deployment-constraints.md)：内网自管且可联网，OS/数据库可推荐，IT 负责运维，无许可采购限制；期望 2026 年底，AI 实现、开发评审、业务定期验收，具体投入仍待落实。
- [明确执行特殊情形与案件关闭例外](issues/12-execution-exceptions-closure.md)：特殊处理以已有人工记录为基础，剩余义务未确认处理完毕时保持未办结，处置明确后按正常条件关闭；不按事件标签自动办结。
- [明确其余业务域的流程与关键规则](issues/13-remaining-business-workflows.md)：现行有效流程作为逐域核对基线，清欠回写两边一致后确认完成，重大业绩初评复核分别授权且允许同人兼任；全部子流程及实际使用仍需核验。
- [选择完整重建的产品技术与业务模块路线](issues/07-architecture-technology-decision.md)：.NET 10 + Vue 3 / Element Plus、单个后端应用按模块组织、PostgreSQL 新业务库、Ubuntu + Nginx 同域部署；模块各管业务规则，必要时允许经验证的 Windows 集成过渡进程。
- [确定新系统身份授权与既有审批衔接](issues/08-identity-approval-contract-decision.md)：新法务配置业务授权并发起查看审批，审批在既有平台办理；回执不明先核对、防重复和迟到覆盖，统一退出，历史归属保留且当前有效身份决定访问；平台实际契约仍须验证。
- [确定历史数据、附件和在途业务保留方案](issues/09-historical-data-attachment-migration.md)：全部业务历史最终迁入 PostgreSQL，旧在途按申请有限过渡，新系统日常办理；已办结默认只读并专门授权更正，允许维护窗口，资产关联与实际演练仍须核验。
- [制定完整业务验收与新旧切换条件](issues/10-cutover-acceptance.md)：案件完整链路先验收，正式覆盖十组；关键历史问题阻断，其余原有异常法务逐项确认，试用演练后一次全量切换，业务/开发/IT 联合放行、IT 执行，优先恢复新系统。
- [收敛重建实施阶段与规格编写入口](issues/11-implementation-spec-handoff.md)：六阶段组织已确认，先进入总规格/案件分规格与前置事实核验，再按真实依赖实施；交接提示词已准备，本轮不执行业务代码。
