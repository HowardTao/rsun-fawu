## 文档明确的契约

| 原文章节 | 明确内容 | 不能据此推定的事项 |
| --- | --- | --- |
| 请求用户授权接口 | authorize 使用 GET，参数含 client_id、redirect_uri、response_type=code、state；认证后携 code 回跳，传入 state 时原样回传 | 当前应用注册、回跳校验和 state 使用方式未验证；不是已证实的 OIDC 接口 |
| 获取授权Token接口(authorization_code模式) | getToken 使用 POST，参数含 client_id、client_secret、code、grant_type；返回 access_token、expires_in、refresh_token、uid | POST 编码、授权码寿命、令牌有效时长单位及刷新接口详细契约未给全 |
| 获取授权Token接口(authorization_code模式) | 原文称“uid为登录用户uid” | 未承诺全局唯一、不可变或不复用；不能直接定为历史迁移后的永久人员主键 |
| 获取用户信息接口 | getUserInfo 使用 GET；参数表含 access_token、client_id；原文称“根据应用配置的属性权限列表，查询用户信息返回” | 没有用户及组织字段 Schema。错误示例提及 uid，但参数表未列出，实际契约需要确认 |
| 应用退出流程 | 前台调用全局退出，中心销毁全局会话，再经 iframe 回调应用本地退出；应用须回收授权并销毁本地会话 | 回收授权接口、退出回调契约、失败恢复及浏览器 Cookie 限制未完整说明 |
| 应用退出流程 | 原文明确“需要前端调用……后台httpclient方式会存在问题” | 不能把服务端发起 HTTP 请求当作已经完成浏览器全局退出 |

文档明确的是授权码模式，未明确 OIDC、ID Token、PKCE、scope、Bearer 传递或发现文档。原文描述回跳地址可按配置 URL 前缀判断，且校验可选择是否启用；当前注册情况与真实匹配规则需要核验。

## 仍需核验的身份与组织关联

- 竹云 uid、旧 LoginName、旧 W2 人员 ID 及新系统人员标识的对应关系；账号改名、禁用及不再存在的历史人员如何关联。
- 用户信息可开放哪些属性，组织树、公司、部门及岗位来自哪个权威来源；不假定竹云已提供组织 Schema。
- 刷新、撤销与本地会话的契约，以及退出当前应用和组织统一登录会话的实际能力。
- 当前应用注册、实际平台版本、开放属性与部署配置。文档可配置不等于环境已启用。

## 与审批衔接的关系

[既有审批静态研究](preserved-integration-contracts.md)已核实发起人使用登录名、本地日志 ID 对应 dataId，再关联业务 GUID 和平台 incident。认证协议变化不能自动解决这些身份和实例关联，也不决定在途审批如何切换。

业务授权责任、审批办理入口与异常处理原则由关联决策事项确认。人员字段和平台能力是待查事实，不由用户凭猜测选协议参数。本记录只完成文档契约核对，不代表集成运行验证通过。
