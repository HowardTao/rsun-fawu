# 产品技术与业务模块路线

关联事项：[选择完整重建的产品技术与业务模块路线](issues/07-architecture-technology-decision.md)。讨论日期：2026-10-22。前后端组合、后端组织、模块职责、部署与集成过渡原则已确认；Q41 已更正为 PostgreSQL。具体版本与兼容性仍待验证。

依据：[原技术研究](research/rebuild-technology-options.md)、[官方候选补充核对](research/technology-candidate-followup.md)、[团队与部署约束](delivery-constraints.md)。完整十组业务均纳入首期，现行有效流程按[已确认原则](issues/13-remaining-business-workflows.md#answer)逐域核对；业务分组不是自动确定的代码模块。

## 已选择的基线及权衡

| 选择 | 已确认路线及原因 | 比较过的另一条路线与代价 |
| --- | --- | --- |
| 后端与前端 | .NET 10 LTS / ASP.NET Core 10，Vue 3 / Element Plus；沿用团队 .NET 和 Element 系组件经验，业务模块提供界面调用的接口 | .NET 为主的 MVC/Razor Pages 或经验证的 Blazor；可减少独立前端工具链，但需验证复杂表格、表单交互及组件支持 |
| 后端组织 | 一个后端应用按业务模块组织与部署；业务规则集中在模块内，界面和后台作业调用模块接口 | 按业务拆独立服务；适合已明确的独立运维、发布或扩容需要，会增加跨进程调用、数据一致性及故障处理工作，目前尚无这类必要性证据 |
| 新业务库引擎 | PostgreSQL，用户因 SQL Server 可能涉及许可问题更正 Q41；接受跨引擎迁移所需的核验 | SQL Server 可减少更换引擎的部分迁移工作，但原选择已被用户更正；旧库仍须按历史保留要求规划 |

.NET 10 的官方支持结束日为 2028-11-14。Vue 3 / Element Plus 不等于旧 Vue 2 / Element UI 的组件代码可直接复用；旧页面与服务端规则仍需重建。前后端分别开发也不自动要求分别部署或跨域访问。

## 旧 SQL Server 依赖与迁移边界

- [项目同步依赖 SqlClient](../../../RSun.FaWu/fwxt.Web/fwxt.MgrSvr/ProjectSync.cs#L6)，并使用[SqlBulkCopy](../../../RSun.FaWu/fwxt.Web/fwxt.MgrSvr/ProjectSync.cs#L83)。
- [清理目标表](../../../RSun.FaWu/fwxt.Web/fwxt.MgrSvr/ProjectSync.cs#L80)使用 T-SQL 与 dbo 表名；[DBML 自增映射](../../../RSun.FaWu/fwxt.Web/fwxt.Web/Data/xcfwxt.dbml#L14)进一步支持旧模型的 SQL Server 依赖。

以上确认的是旧源码依赖，不是服务器实际版本、部署、兼容级别或同步作业启用情况。新业务库改用 PostgreSQL 后，须核对旧 SQL、数据映射、组织审批关联及报表依赖；不默认迁移外部平台数据库或让新旧系统同时修改同一份数据。历史资产、新旧写入权威及外部库访问由后续迁移和集成决策明确。

当前数据库决定见[新业务库采用 PostgreSQL](../../docs/adr/0002-postgresql-business-database.md)；[原 SQL Server 决定](../../docs/adr/0001-retain-sql-server-engine.md)已标记被取代。

[PostgreSQL 许可与 .NET 10 适配核对](research/postgresql-compatibility-followup.md)已核实官方许可及规划日期之前发布的 Npgsql 适配包；数据访问方式和具体版本尚未选择，跨引擎迁移仍须验证。

## 模块职责基线（已确认）

以下按业务对象及操作组织职责，同属一个后端应用；不要求每行独立项目、数据库或部署单元。现有业务分组全部覆盖，代码内部进一步拆分以真实业务规则为依据。

| 模块职责 | 负责的业务对象和主要操作 | 与其他模块或平台的协作 |
| --- | --- | --- |
| 案件办理 | 案件登记、立项、参与关系、程序事实、阶段内进度、审理结案及履行跟踪、关闭 | 关联冻结、律师委托与联系单；所属业务规则决定案件如何变化 |
| 查封冻结 | 冻结账户与资产台账、冻结/解封金额和期限、案件关联 | 提供关联信息及期限依据，不由案件页面重复计算台账规则 |
| 律所律师与委托 | 律所律师主数据、合作与案件/项目委托、框架合同关联、已确认的费用和评价流程 | 通过关联标识连接案件、项目与合同；接入既有审批，不把审批同意等同费用结清 |
| 清欠 | 接收、人员变更、退回等有效流程及结果跟踪 | 明源回写两边一致后确认操作完成，异常待核对并跟踪 |
| 合同与投融资 | 既有合同关联、重大合同履约、投融资项目、尽调进展及投后履约 | 律师委托交由对应模块办理；不凭合同名称新增签署平台 |
| 非诉事务 | 综合法律事务、培训、制度专题、知识产权、行政处罚等各自的记录与规则 | 各类别保留实际差异，不预设一张万能表或统一审批流程 |
| 法律事务与联系单 | 协作事项、申请、办理进展及验收 | 关联案件或其他事项；业务模块决定申请通过、验收通过各自的成果 |
| 绩效与重大业绩 | 申报、参与比例、评分、初评、复核和汇总 | 初评复核分别授权，允许同人兼任；有效公式和周期待业务核验 |
| 文件知识与报表入口 | 外部文件/知识应用与业务报表的法务端入口及业务参数 | 保留外部平台本体；法务端的查询与参数仍受相应业务授权约束 |
| 共用能力 | 身份及组织映射、角色授权、附件关联、审批衔接、通知与作业运行 | 平台适配处理协议、调用结果及关联标识；业务模块决定本模块状态、金额和办结效果。提醒条件由业务模块提供，运行与发送由共用能力承接 |

业务记录由所属模块负责维护，其他模块通过其接口访问或请求操作；不直接修改另一模块内部记录。审批回传交给所属业务模块处理，不由通用回调把所有业务状态统一改为完成。物理表结构与新旧写入归属由后续迁移决策明确。

## 部署与集成过渡原则（已确认）

- 主应用采用 Ubuntu 24.04 LTS，由 Nginx 提供同域入口：前端静态文件与后端接口使用同一站点。PostgreSQL 的具体版本、部署资源及备份方案由 IT 按所选版本核定，不默认与主应用安装在同一服务器。
- 优先采用现有平台支持的接口直接适配。只有运行验证证明旧审批或其他组件必须依赖 Windows / .NET Framework 时，才允许隔离的 Windows 集成过渡进程，并明确调用责任、失败处理与退出条件。
- Vue 3 不支持 IE11；客户端实际浏览器及组件使用由环境核验形成验收矩阵。原型、包版本、安装和兼容验证留到后续实施规格与验证工作。

## 仍需继续明确

- 各业务模块内部的用例、字段与接口规格，以及真实跨模块协作和共用能力的具体契约。
- 客户端浏览器验证、PostgreSQL 部署资源及备份恢复；后台作业是否需要独立进程按实际运行需求判断。
- 所选框架、组件、数据库及驱动的具体版本和兼容验证；登录与审批组件是否需要 Windows 过渡进程须以实测为准。
- 未来 MCP 入口复用已验证的业务模块接口，具体工具和 AI 协同场景仍在本轮范围外。

本轮不安装框架、不创建业务工程、不连接数据库或调用集成平台。路线选择与运行验证分别记录。
