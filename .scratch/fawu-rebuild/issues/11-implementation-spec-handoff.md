## Answer

采用[六阶段路线](../implementation-roadmap.md)：规格与事实核验 → 必要底座与历史小样 → 案件完整链路 → 其余业务按依赖逐域完成 → 全历史对账与完整试用/演练 → 联合放行、一次正式切换与旧链退出。每阶段有交付结果与通过条件，首期十组完整范围保持有效，案件是首个端到端验收里程碑。

下一步按[交接提示词](../spec-handoff-prompt.md)调用 `/to-spec`，生成重建总规格索引与案件完整链路分规格，按需引用既定业务、技术、迁移和验收决定。测试主要通过业务用例接口验证外部行为，关键 UI 与真实平台另作贯通验证；具体接口和状态全集在规格中设计，不能编造旧测试先例或未证实字段。

稳定身份/组织 Schema、审批实际契约、真实数据与附件/后台状态、各域有效子流程、组件版本、人员投入与演练仍为前置核验。它们不被本轮的决定完成状态视为已经通过；所依赖用例实现等待相关事实明确，事实揭示新产品取舍时再建立具体决策事项。

本事项收敛实施组织与交接，不执行规格合成、业务实现、数据迁移或生产部署。工期在核验与投入明确后估算，2026 年底仍为期望。
