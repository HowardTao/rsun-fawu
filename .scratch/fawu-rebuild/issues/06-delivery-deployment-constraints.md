## Question

完整重建必须满足哪些上线时间、运行平台、数据库、网络、部署运维和团队维护约束？区分组织硬约束与可选偏好，为技术选择提供边界。

## Dependencies

无，可独立推进。

## Completion criteria

- 明确新系统部署目标及旧 Windows 测试环境可用于哪些验证。
- 记录上线期限、维护团队能力、采购/许可证及系统接入限制；未知项明确待查。
- 不自行承诺时间、默认容器/Linux 或指定数据库。

## Discussion materials

- [上线、部署与维护约束](../delivery-constraints.md)：记录已确认的部署条件、年底期望、运维及评审分工，并列出实际核验及排期输入。

## Comments

- Q28–Q30：用户确认公司内网自管服务器，操作系统和数据库暂无既定硬要求，可推荐；暂无硬截止日期，期望 2026 年底上线。开发人员熟悉 Element UI 与 .NET，AI Agent 主要实现、开发人员评审。网络及采购限制、长期维护责任与评审投入尚待明确，本事项保持 `claimed`。
- Q31–Q33：用户确认能联网且无访问限制，公司有专门 IT 负责，没有许可及采购限制；集团法务和业务经办人可以定期参与验证、迁移核对与验收。评审人数及时数仍未量化，作为估算前待落实的输入记录。

## Answer

详细约束见[上线、部署与维护约束](../delivery-constraints.md)：公司内网自管部署，OS 与数据库可推荐，能联网且无已知访问限制，公司 IT 负责运维，无许可及采购限制。暂无硬截止日期，期望 2026 年底上线；AI Agent 主要实现，开发人员评审，业务方定期参与验证与验收。

技术候选已补充官方资料，最终选型未决定。评审投入、具体资源及运维责任细分尚待落实；年底是期望，当前没有据此作出工期或上线承诺。部署约束决策完成，不代表实际网络、组件、数据库及备份恢复已验证。
