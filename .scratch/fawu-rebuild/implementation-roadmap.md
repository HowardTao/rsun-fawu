# 完整重建实施阶段与规格交接

关联事项：[收敛重建实施阶段与规格编写入口](issues/11-implementation-spec-handoff.md)。更新日期：2026-10-22。用户已确认六阶段组织及规格交接方式；本轮完成路线与提示词，规格、运行核验和业务实现进入后续阶段。

## 实施阶段

| 阶段 | 交付结果 | 通过标准与依赖 |
| --- | --- | --- |
| 1. 规格与事实核验 | 重建总规格索引、案件分规格、逐域有效业务覆盖和待核验清单；核实身份组织、审批、旧结构/SQL、附件及后台实际情况 | 已确认与未证实分开，影响用例实现的字段、规则和平台能力先核实；实际角色、法务分工及评审/IT 责任落实。可以先起草规格，但不能把未知补成既定规则 |
| 2. 必要底座与小样验证 | .NET 10 + Vue 3 / Element Plus + PostgreSQL 可运行底座，必要的身份授权、审批/附件衔接；代表性历史映射和金额时间查询验证 | 锁定版本并验证运行与真实平台适配；操作与范围配对通过；历史小样对账。Windows 过渡进程仅在必要性获证实时采用，数据访问方式在证据基础上选择 |
| 3. 案件完整链路 | 登记、立项补正、程序事实和进展、履行与关闭；必要的律师委托、冻结关联、附件、旧在途处理及移交 | [案件流程](product-workflows.md)、[特殊处理](execution-exceptions.md)和[验收试点](cutover-acceptance.md)的正常/异常行为通过，业务确认；这是首个端到端验收里程碑 |
| 4. 其余业务逐域完成 | 查封冻结、律所律师与委托的完整范围、清欠、合同投融资、非诉、法律事务联系单、绩效业绩、文件知识与报表，以及剩余共用/后台能力 | 每域按实际依赖编写分规格、实现并验收；保留规则作旧环境对照，改变规则按新规格验证。前阶段已实现的共用或关联用例复用，不凭一个代表页面宣布整域完成 |
| 5. 全历史对账、试用与演练 | 全部法务历史迁移方案及执行结果、人员/审批/附件对照、异常处置清单、完整业务试用、任务接管和恢复演练 | [历史保留](historical-migration.md)与[完整验收](cutover-acceptance.md)门槛通过；关键异常解决，其余原有异常法务逐项确认；实际维护和恢复时长得到验证 |
| 6. 一次正式切换与旧链退出 | 联合放行、维护窗口最终同步、切换验证，旧在途完成后的结果核对和对应旧链退出 | 法务、开发、IT 分职责确认，IT 执行；新系统日常办理，旧链仅处理原在途；通知/同步接管单一归属明确，关键故障保留增量及外部结果并优先恢复新系统 |

阶段是研发和验证顺序，首期始终完整覆盖[十组业务](scope-review.md)。不相互依赖的规格、核验和模块工作可按真实依赖安排；具体批次与工期在前置证据、分规格及可投入人员明确后估算，2026 年底为期望而非已验证承诺。

## 前置事实的处理

当前旧系统可用，但尚未连接测试环境。以下事实必须落实到相关规格和实现的验证条件，避免将静态源码或文档示例当作运行结果：

- 竹云身份稳定标识、人员/组织 Schema、旧登录名对照、当前应用注册及刷新/退出能力，见[SSO 文档核对](research/sso-document-contracts.md)。
- 审批实际发起/回传契约、来源和确认机制、状态查询与恢复、旧实例和表单依赖，见[集成研究](research/preserved-integration-contracts.md)。
- 真实数据库结构、业务状态/金额语义、SQL/存储过程/报表、规模与增量、附件来源及有效任务，见[历史核验清单](historical-migration.md)。
- 各域实际有效子流程、组织职责、首期角色授权与评分等有效规则，由集团法务确认、经办人补充，事实以代码和环境核验。
- 具体框架/数据库/驱动版本、目标资源、浏览器、评审投入和 IT 责任及恢复演练，见[部署约束](delivery-constraints.md)与[PostgreSQL 适配事实](research/postgresql-compatibility-followup.md)。

核验影响已定产品取舍时回到相应决策事项；字段、接口和运行细节在分规格中补齐。路线确认不等于前置核验通过，关联用例实施应等待所需事实明确。

## 规格与 Agent 工作方式

下一步使用 `/to-spec`，先合成重建总规格索引和案件完整链路分规格，再按实际依赖展开其他域。总规格保持范围、约束、依赖及验收索引；分规格描述用户故事、业务模块接口、规则、外部影响、历史映射和可验证成果。

测试主要通过业务用例接口验证授权、状态、金额、外部效果和历史关联；关键界面链路与真实平台契约另作贯通验证。已有案件试点和接口授权预期作为测试依据，具体接口形状在规格中设计。旧工程未发现可直接继承的自动化测试体系，不编造测试先例。

AI 按可审查的用例/任务实现，开发人员评审，业务与 IT 按职责验证。任务输入引用对应规格、相关决定与代码事实，完成时给出改动及验证结果；事实缺口要明确记录并先核验，不能靠补全想象推进相关业务实现。

可复制入口：[规格交接提示词](spec-handoff-prompt.md)。本轮不直接运行 `/implement`、迁移或部署。
