# 完整业务验收与切换基线

关联事项：[制定完整业务验收与新旧切换条件](issues/10-cutover-acceptance.md)。更新日期：2026-10-22。试点、完整验收、历史异常、一次全量切换、联合放行与优先恢复新系统均已确认。没有执行测试或上线。

## 首个端到端验收试点（已确认）

优先用案件从登记、立项审批到审理结案、履行办结与关闭，验证界面、业务模块、身份授权、既有审批和历史关联能贯通。试点是实施与验证顺序，首期仍按[完整十组范围](scope-review.md)交付，不把试点替代正式验收。

建议案例使用可恢复测试环境及经核对的样本，期望按[案件流程基线](product-workflows.md)、[特殊执行原则](execution-exceptions.md)与[迁移过渡规则](historical-migration.md)确定：

| 场景 | 应验证的成果 |
| --- | --- |
| 登记、退回补正、重提通过 | 同案保留每次提交和处理历史，正式立项以通过为准 |
| 多角色与主责移交 | 全集团查看与本人修改范围成对生效；移交后按当前关系重判访问，接口和附件同样遵守授权 |
| 程序事实与内部审批并行 | 法院二审已受理时记录二审事实，内部上诉申请仍可审批中；迟到结果不能覆盖新事实 |
| 结案及未履行义务 | 审理结案与执行完毕分开，义务未明确处理完毕不能关闭；特殊事件不自动归零或办结 |
| 旧在途委托与新办理 | 原申请资料受限，其余合法办案进展可维护；同一申请唯一处理链，重复结果不重复产生业务效果 |
| 历史及附件 | 历史身份、状态、金额和材料关联可追溯；已办结只读并专门授权更正，支持原有有效文件访问 |

具体状态全集、字段与真实测试数据由规格及环境核验补齐，案例表不声称完整案件测试已经覆盖。

## 正式验收门槛（已确认）

| 维度 | 门槛与证据 | 确认职责 |
| --- | --- | --- |
| 全部业务覆盖 | 十组逐域列出有效流程及成果；保留行为对照旧环境，已确认调整按新规格验证，记录差异原因。代表页面存在不足以证明全组完成 | 集团法务统筹，经办人验证场景 |
| 权限与身份 | 自定义多角色、操作与范围配对、组织/参与关系、停用和移交后的访问均有验证；真实 SSO 映射与退出链验证 | 开发与 IT 验证，业务核对角色范围 |
| 审批及外部写入 | 实例关联、补正、回执不明、重复/迟到、部分成功恢复及在途归属有证据；清欠两边一致后确认完成 | 开发、IT 及对应业务确认 |
| 历史数据与附件 | 关键金额、时间、状态、人员、审批及文件关联对账，转换说明可追溯；异常有清单和处置依据 | 开发/IT 对账，法务确认业务含义，经办补材料 |
| 报表、通知与后台 | 有效口径、实际启用任务、数据写入及消息发送归属明确，避免旧新同时无意发送或同步 | 业务确认口径，开发/IT 确认接管 |
| 运行及恢复 | Ubuntu/Nginx、PostgreSQL、真实平台适配、备份恢复、最终同步与维护窗口演练有结果 | IT 及开发，业务确认办理可用性 |

每项证据记录场景、前提/样本、期望、实际结果、差异及确认者；开发评审、自动验证与业务验收分别保留证据。人员及时数、具体环境、样本和外部平台支持仍须落实，年底仅为期望日期。

## 故障恢复原则（已确认）

关键故障时先停止新业务写入，核对并保留切换后新增修改、已受理的审批及外部处理结果，再按演练验证的路径恢复办理。还原本地数据库不能自动撤销外部审批或通知；回退必须考虑切换后的增量与仍在运行的外部平台。

优先恢复新系统服务与业务结果，旧系统仅继续已经确认的在途审批过渡，不要求全面接管新业务。不能默认新状态和 PostgreSQL 数据可直接反向写旧库。恢复时间、可接受维护时长及具体触发条件由演练和业务/IT 确认，不写未经验证的承诺。

## 后台任务与旧链的接管核验

同一次申请、同一业务对象的普通写入沿已定归属处理。每项实际启用的同步与提醒任务，在切换清单记录当前执行者、目标执行者、停启顺序、对应业务/申请、重复处理规则、核验结果与负责人；接管验证应证明不会无意重复写入或发送。

只保留在途审批需要的旧处理链及必要通知；结果核对纳入新业务后退出对应旧链。源码中被注释或仅存在分派的任务，先核验实际是否启用，不据此直接启停。旧链退出须有剩余实例、结果及未处理回传的核对依据，不能仅按日期删除。

## 历史异常、切换节奏与放行（已确认）

- 原有历史异常按影响区分：关键金额、义务、身份权限、在途审批和必需材料问题阻止切换；其他经集团法务逐项确认后保留原始证据、缺失/冲突说明及处置清单。迁移新产生的数据损坏或丢失不能当作原有异常接受。
- 先在测试环境完成业务试用与迁移演练，验收达标后在维护窗口进行一次全量正式切换；旧在途仅按既定有限过渡保留，不采用按组织分批的生产启用方式。
- 集团法务确认业务与历史例外、开发确认评审及技术验证、IT 确认部署备份恢复；联合放行后由 IT 执行切换。具体负责人在实施安排中落实。
